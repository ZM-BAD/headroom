## 横切原则（适用于所有里程碑）

- **跨浏览器别放最后。** 001 验收闸门 3 已含 Firefox/Edge **冒烟**（能装能开、基础拦截能跑）；004 只做深度 QA 与边角补齐。早抓 Chrome 专属假设，别让它复利。
- **每个里程碑一个主题。** 不捆不相干的事。
- **先 1 家验通再铺开。** 架构按 adapter 解耦，但验证从 DeepSeek 起步最便宜。
- **spec = 当前真值。** 推倒重来时直接覆盖；不留删除线、不留"上一版"考古。Git 是历史，spec 只反映当下。

## 关于"国际化"——立项时拆清的两件事

一句话里混过两个完全不同的东西，这里钉死别再捆：

- **Token 估算按文字脚本校准（→ 001 引擎 / 004 校准）**：估算系数是「平台 × 脚本」矩阵（CJK / Latin / 西里尔 / …）。这是**正确性**，无论 UI 是什么语言都有价值。优先级高。v1 在 001 做中/英，004 扩更多脚本 + 按平台 tokenizer 校准。
- **扩展 UI 本地化（不单列 spec）**：面板/设置界面翻译成其他语言。技术上是 `_locales/` 字典 + 一个语言下拉（001 设置视图已有"语言 [自动▾]"项）。**技术难度低，不单独做 spec**；有海外用户后直接加字典条目。

两者互不依赖。别再捆一起。

## 不单列 spec 的能力（落到哪）

- **新增平台（Claude/Grok/MiniMax…）**：不单列 spec。001 的 adapter 契约就是为这个设计的——新增平台 = 注册 + 一个 `adapters/<platform>.ts`（拦 send / 抓 answer / 拉历史 / 拉列表 / 拦删除 + 默认系数 + 默认 contextLimit）。市占率驱动，有需求时照契约加即可。
- **UI 翻译成更多语言**：不单列 spec（见上）。
